# Разработка

Приложение написано на Swift, SwiftUI и AppKit. Сборка использует системные фреймворки; отдельного backend-сервера или базы данных для аккаунтов нет.

## Локальная сборка

Проверенная архитектура — Apple Silicon, компилятор — Swift 6.2. Приложение собирается с минимальной версией macOS 14; языковой режим компилятора в скриптах — Swift 5. Вариант Intel (`LIST_ARCH=x86_64`) предусмотрен скриптом, но не проверен.

```sh
./scripts/doctor.sh
./build.sh
```

Результат: `dist/Лист — Reader for Engineers.app`. Скрипт собирает во временную папку, подписывает приложение ad hoc и проверяет подпись перед переносом результата. Аккаунт Apple Developer не нужен.

```sh
./scripts/install.sh   # Собрать и скопировать в ~/Applications
./scripts/package.sh   # Собрать ZIP приложения в dist
```

Публичная сборка имеет отдельное имя и bundle ID `com.readerforengineers.ListReader`. Она использует `~/Library/Application Support/ReaderForEngineers/`, а не личный профиль предыдущих сборок автора.

## Изолированный профиль для разработки

Используйте отдельный каталог данных, чтобы не затрагивать свою библиотеку:

```sh
READER_DATA_DIR="$PWD/.local-reader-data" \
  "./dist/Лист — Reader for Engineers.app/Contents/MacOS/ListReader"
```

`READER_DATA_DIR` задаёт каталог библиотеки, переписки и практики. Он не заменяет хранилище авторизации Codex и системные настройки macOS. Не запускайте одновременно несколько экземпляров с одним каталогом данных: приложение не рассчитано на совместную запись профиля.

Для запуска без ИИ ничего дополнительно настраивать не нужно. Для ручной проверки ответов выполните собственную авторизацию по [инструкции](SETUP.md). Не копируйте `auth.json`, чужой `CODEX_HOME` и личные библиотечные данные в проект.

## Как устроен поиск помощника

1. При отправке вопроса фиксируются книга и место чтения.
2. Модель получает текущую страницу, выделение, метаданные и ограниченную историю чата.
3. Если нужен поиск, модель возвращает структурированный запрос. Приложение выполняет его локально: сначала в текущей главе, затем в книге до зафиксированной позиции.
4. В модель передаются найденные выдержки с местоположением и описанием покрытия. Действуют ограничения числа запросов и общего объёма текста.
5. Возвращается итоговый ответ. Смена книги не переносит ответ в чужой диалог.

CLI не получает инструменты для чтения произвольных файлов, запуска команд или сетевого поиска. Книгу, текст упражнения и решение нужно сохранять как недоверенные данные в пользовательском payload, отдельно от инструкций приложения.

В практике цитата перед показом проверяется на присутствие в переданном материале. Переход к источнику использует сохранённую страницу PDF или главу текстовой книги. Совпадение цитаты подтверждает её происхождение, но не гарантирует правильность рассуждения ИИ.

## Проверки

```sh
./scripts/test.sh
```

Основной набор работает без авторизации ChatGPT, сети и Docker. Для генерации файлов нужен Python 3. Проверки используют временные каталоги, искусственные PDF и сгенерированные файлы:

| Набор | Что проверяет |
| --- | --- |
| `CodexSetupSmoke` | Обнаружение и совместимость CLI на подставном исполняемом файле |
| `ChatAssistantSmoke` | Протокол ответа и последовательность поиска с подставной моделью |
| `ChatBookSearchSmoke` | Границы поиска, заголовки и выбор фрагментов |
| `LibraryManagementSmoke` | Порядок, архив, сохранение и пустую библиотеку |
| `ImporterTests` | Импорт сгенерированных книг разных форматов |

Тесты протокола не оценивают качество живой модели и не заменяют ручную проверку UI. Перед выпуском пройдите [демонстрационный сценарий](DEMO.md): первый запуск, собственный вход, импорт, сохранение места, вопрос, практика и переход к источнику. Проверяйте также отмену запроса и закрытие/повторное открытие приложения.

Дополнительные проверки запускаются только явно:

```sh
./scripts/test.sh --ui           # Синтетический PDF и размеры панелей; нужен GUI
./scripts/test.sh --live-chat    # Собственный Codex, интернет и лимит аккаунта
./scripts/test.sh --live-coach   # Живая проверка практики на синтетическом материале
./scripts/test.sh --docker      # Работающий Docker; возможна загрузка образов
```

Эти режимы не входят в основной офлайн-набор. Полный список доступен через `./scripts/test.sh --help`.

## Перед публикацией

Проверьте diff и список добавленных файлов. В Git не должны попасть каталоги пользовательского профиля, книги, учётные данные, логи и результаты сборки. `.gitignore` помогает, но не удаляет уже отслеживаемые файлы. Для нового демонстрационного профиля используйте собственные тестовые данные и настоящие скриншоты.

При отчёте об ошибке полезны версия macOS, архитектура, версия Swift/Codex и шаги воспроизведения. Текст книги, переписку и код решения прикладывайте только в том объёме, которым готовы поделиться.
