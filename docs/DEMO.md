# Демонстрация: от страницы к применению

Цель — показать один законченный учебный эпизод: читатель разобрал идею из технической книги, проверил её кодом и вернулся к исходному объяснению. Изображения в README — настоящие экраны приложения, а не макеты.

Для примера используется книга Мартина Клеппмана «Высоконагруженные приложения», предоставленная владельцем локально. PDF не распространяется с проектом. Для повторения подойдёт ваша книга с извлекаемым текстом про задержки, процентили или другую тему, которую можно проверить небольшим упражнением.

## Подготовка

1. Соберите приложение и запустите отдельный профиль через `READER_DATA_DIR`, как описано в [руководстве разработчика](DEVELOPMENT.md).
2. Добавьте свою книгу. Выберите страницу с содержательным объяснением; обложка и оглавление не показывают пользу помощника.
3. Войдите через собственный ChatGPT. Для выполнения кода подготовьте Docker.
4. Уберите из кадра личные файлы, другие переписки и уведомления. Используйте отдельную демонстрационную беседу и новое упражнение.

Не заполняйте интерфейс заранее придуманными ответами, не заменяйте вывод программы вручную и не рисуйте элементы поверх скриншотов. Текст вопроса, ответ модели и результат запуска должны появиться в самом приложении.

## Сцена 1. Спокойное чтение

В демонстрационном PDF Клеппмана страницы 37–39 содержат объяснение характеристик задержки и рисунок 1.4. Номера относятся к PDF, а не к печатной нумерации; в другом издании найдите соответствующий раздел. Выберите вид **«Бумажный»**, подходящий масштаб и оставьте видимыми границы страниц. Снимок должен показывать реальное чтение, без перегруженных панелей.

**Файл:** `screenshots/01-reading.jpg`.

**Что доказывает:** техническую книгу удобно читать, место сохраняется, вспомогательные инструменты не занимают экран постоянно.

## Сцена 2. Вопрос без копирования контекста

Откройте помощника через **⌘J**. Вопрос для страницы про хвост задержек:

> Сопоставь рисунок 1.4 и текст перед ним: почему средняя задержка может обмануть? Объясни p95/p99 на 100 запросах. До 100 слов, укажи страницы.

Дождитесь настоящего ответа. Оставьте видимыми вопрос и полезную часть ответа. Страницу можно показать рядом, если ширины экрана хватает, либо отдельным предыдущим кадром. Если выбран другой материал, адаптируйте вопрос к нему — пример должен опираться на открытый текст.

**Файл:** `screenshots/02-context-chat.jpg`.

**Что доказывает:** не нужно переключаться в другой чат, вручную объяснять название книги и копировать страницу. Модель отвечает по текущему месту, а при необходимости запросит более широкий поиск.

## Сцена 3. Проверка идеи кодом

Откройте **⌘⇧P**, выберите текущую страницу и Python, нажмите **«Создать задание»**. Задание генерируется по выбранному материалу; точное условие и код зависят от полученного задания.

В снятом примере ИИ создал задание **«Медиана скрывает медленные запросы»** по странице 39 PDF. Сервис A отвечает на все 100 запросов за 100 мс. У сервиса B 98 ответов занимают по 100 мс, ещё два — по 1500 мс. Нужно вернуть медиану, p99 и результат проверки требования: медиана строго меньше 200 мс **и** p99 строго меньше 1000 мс.

В условии явно задан способ вычисления p99: nearest rank, элемент на позиции `ceil(0.99 × n)` в отсортированном списке, считая с единицы. Это выбранная конвенция упражнения, а не единственный способ вычисления выборочного процентиля.

Напишите решение именно полученного задания, нажмите **«Запустить»**, затем **«Проверить решение»**. В снятом примере настоящий вывод Python:

```text
A: median=100 ms, p99=100 ms, SLA=True
B: median=100 ms, p99=1500 ms, SLA=False
Одинаковая медиана скрывает медленные 2% запросов.

Код завершения: 0
```

При повторении можно сначала допустить понятную ошибку и исправить её после подсказки. На опубликованном экране показано выполненное решение.

Расширьте редактор перетягиванием границы. В кадре должны помещаться условие, код и настоящий вывод запуска. Не показывайте пустой редактор как завершённый пример практики.

**Файл:** `screenshots/03-practice.jpg`.

**Что доказывает:** прочитанную идею можно применить и проверить, оставаясь рядом с материалом. Вывод выполнения отделён от оценки ИИ.

## Сцена 4. Проверяемая подсказка

Нажмите **«Проверить решение»**. Для исполняемого формата приложение сначала выполняет код, затем передаёт результат на разбор. В снятом примере ИИ проверил индекс p99, строгие неравенства и вывод, отдельно указал ограничение проверки небольшой выборкой. Разбор содержит два проверенных фрагмента страницы 39 PDF.

Нажмите **«Открыть в книге»** на карточке цитаты. Приложение вернётся к исходной странице и выделит фрагмент. Это снято отдельным кадром; номер PDF может отличаться от печатного номера.

**Файлы:** `screenshots/04-source-evidence.jpg` — разбор и цитата; `screenshots/07-source-jump.jpg` — переход и выделение в книге.

**Что доказывает:** можно проверить основание подсказки и перечитать авторское объяснение. Наличие цитаты подтверждает происхождение текста, а не безошибочность ответа ИИ.

## Сцена 5. Собственный вход

Откройте **Настройки → ChatGPT**. Покажите состояние подключения или понятные действия для установки CLI и входа. Не снимайте браузер авторизации, токены, email или содержимое файлов учётных данных.

**Файл:** `screenshots/05-setup.jpg`.

**Что доказывает:** разработчик подключает свой аккаунт; в приложении нет общей авторизации автора. Для чтения подключение не требуется, Docker вынесен в необязательную настройку запуска кода.

## Сцена 6. Чтение рядом с работой

Включите **⌘⇧M**. Покажите компактное окно на нейтральном фоне или рядом с демонстрационным кодом без личных данных. Не сжимайте страницу до неразборчивого текста. Верните окно, затем скройте и покажите приложение через **⌃⌥Пробел**.

**Файл:** `screenshots/06-compact.jpg`.

**Что доказывает:** можно держать нужный фрагмент рядом с рабочим окном и быстро возвращаться к чтению.

## После съёмки

Проверьте каждое изображение в масштабе 100%: читаемость, личные данные и соответствие подписи реальному действию. В репозиторий добавляются только снимки. Демонстрационный PDF, JSON переписки, черновики и данные авторизации остаются вне Git.

Повторный запуск приложения должен восстановить страницу и решение. Публичная сборка на новом профиле должна открываться без этой демонстрационной библиотеки.
